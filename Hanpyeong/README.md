# 한평상회

한 평짜리 구멍가게에서 시작해 그룹 회장까지 올라가는 iOS 경영 시뮬레이션 게임 (SwiftUI, iOS 17+).

## 실행 (Mac + Xcode 16 이상)

```bash
brew install xcodegen
cd Hanpyeong
xcodegen            # project.yml -> Hanpyeong.xcodeproj 생성
open Hanpyeong.xcodeproj
```

## 게임 구조

| 시스템 | 내용 |
|---|---|
| 계산대 (탭) | 가게를 누르면 돈이 들어온다. 계산대를 8단계까지 바꿀 수 있다 |
| 점포 | 18개 업종: 붕어빵 노점·구멍가게 → 분식집·코인빨래방 → 카페·치킨집·PC방 → 편의점·헬스장·고깃집 → 대형마트 → 프랜차이즈 본사·호텔 → 물류센터·테마파크 → 백화점·항공사 → 지주회사 |
| 업종 성격 | 노점(임대료 없음, 겨울 강세) · 무인(직원 불필요, 비 오면 대목) · 야간형(저녁 매출 폭발) · 불황에 강함 · 관광형(여름·맑은 날 강세) |
| 계절·날씨 | 하루 = 달력 3일, 120일 = 1년. 봄·여름·가을·겨울과 맑음·흐림·비·눈·폭염·한파가 업종마다 다르게 작용 |
| 평판 | 0~100. 손님 수 ×0.8~×1.2. 결정 이벤트와 시설 투자로 오르내림 |
| 시설 투자 | 점포마다 7종: LED 간판, 배달 앱, SNS 마케팅, 인테리어, 키오스크, 단골 카드, 프리미엄 설비 |
| 인재 | 18명. 장인·세무사·중개사·인플루언서·전문경영인 등, 업종 매출이나 비용·대출·매매 조건을 바꿔준다 |
| 결정 이벤트 | 23종. 외상, 임대료 인상, 방송 섭외, 위생 점검, 별점 테러, 투자 사기, 세무조사, 월드컵 등. 선택에 따라 돈·평판·매출이 달라진다 |
| 할 일 · 업적 | 매일 바뀌는 할 일 3개, 업적 35개 |
| 재계 순위 | 가상의 회사 12곳과 순자산 경쟁 |
| 레벨 | 1~100. Lv 10·25·50·75·100마다 매출 2배. ×1/×10/MAX 단위로 구매 |
| 직원 | 1명당 매출 +35%, 대신 매일 일당이 나간다 |
| 지역 | 9곳(관광지 2곳 포함). 지역마다 유동인구, 임대료, 자리 수, 시세지수가 다르다 |
| 매물 | 매일 다른 사장님이 내놓는 가게를 사들인다 (급매·프리미엄, 사연 포함) |
| 매각 | 매수 희망자 3명의 제안 중 골라 판다. 수수료·세금 5% |
| 건물 | 지역마다 3채. 사면 매일 월세가 들어오고, 그 지역 내 점포 임대료는 0원 |
| 시세 | 지역 시세지수가 매일 변한다. 개업비, 매물가, 건물값, 매각가에 모두 반영된다 |
| 뉴스 | 축제, 공사, SNS 열풍, 불황, 재개발 같은 사건이 매출과 시세를 흔든다 |
| 은행 | 순자산의 50%까지 대출. 일 이자 0.25% |
| 직함 | 순자산 기준 9단계. 올라갈 때마다 새 업종과 지역이 열린다 |
| 오프라인 | 앱을 끈 동안에도 최대 8시간까지 평소 수익의 50%를 번다 |

하루는 실제 시간 40초다. 매출은 계속 쌓이고, 임대료·인건비·이자는 마감 때 한꺼번에 빠진다.

## 파일

```
Hanpyeong/
  App/        앱 진입점, 탭, 온보딩, 승급 연출, 오프라인 정산
  Theme/      색·글꼴·버튼 스타일, 한국식 금액 표기(만·억·조·경)
  Model/      Catalog.swift: 밸런스 숫자 전부 / Entities.swift: 저장 데이터 구조
  Engine/     Game.swift: 게임 규칙 전체 / News.swift: 뉴스 이벤트
  Views/      가게 · 매물 · 장부 · 회사 탭 화면
  Resources/  나눔명조 글꼴과 OFL 라이선스 전문
```

**밸런스는 `Model/Catalog.swift` 한 파일에서만 조정한다.** 개업비, 매출, 레벨 비용 증가율, 직함 기준, 대출 이자 같은 값이 모두 여기 있다.

## 출시 전 확인할 것

- **상호 상표 검색**: 출시 전 KIPRIS(키프리스)에서 "한평상회"를 검색해 같은 이름의 게임·앱 상표가 있는지 확인한다.
- **글꼴 라이선스**: 나눔명조는 SIL OFL 1.1이라 앱에 넣어 배포할 수 있다. 라이선스 파일을 함께 넣어 두었다. 글꼴 파일만 따로 팔면 안 된다.
- **실존 브랜드 금지**: 가게 이름에 실제 프랜차이즈 상표(편의점·치킨·카페 브랜드)를 쓰지 않는다. 지금 들어 있는 이름은 모두 지어낸 것이다.
- **등급분류**: 앱스토어 연령 등급 설문을 정확히 작성한다. 국내 등급분류는 앱스토어의 자체등급분류 제도로 처리된다.
- **결제를 넣을 경우**: 확률형 아이템(뽑기)을 넣으면 확률을 공개해야 한다(게임산업법, 2024.3. 시행). 미성년자 결제 환불 규정도 확인한다.
- **개인정보**: 지금은 아무 데이터도 밖으로 보내지 않는다(저장은 기기 안 JSON 파일). 광고 SDK나 분석 도구를 넣으면 개인정보처리방침과 App Store 개인정보 라벨을 작성해야 한다.

## 자동 빌드 · TestFlight

- `.github/workflows/hanpyeong-build-check.yml`: `Hanpyeong/` 아래 파일이 main에 푸시되면 시뮬레이터용으로 컴파일만 해 본다.
- `.github/workflows/testflight-hanpyeong.yml`: Actions 탭 → **한평상회 TestFlight → Run workflow**. FLYON·구독온·TRADEX와 같은 팀, 같은 시크릿(`APP_STORE_CONNECT_*`), 같은 임시 서명 방식(`ci/apple_signing.py`)을 쓴다.
- 번들 ID는 다른 앱들처럼 `com.flight.flyon`을 쓰고, 빌드 번호가 겹치지 않도록 버전은 **1.2**, 빌드 번호는 **30000 + 실행 번호**로 올린다.
- 같은 번들 ID라서 TestFlight에서 한평상회를 설치하면 폰에 있던 FLYON·구독온·TRADEX 테스트 빌드를 덮어쓴다. 한평상회를 따로 두려면 App Store Connect에 새 앱(예: `com.flight.hanpyeong`)을 만들고 워크플로와 project.yml의 번들 ID를 바꾸면 된다.
